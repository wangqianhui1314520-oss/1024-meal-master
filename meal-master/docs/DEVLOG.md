## 三、Bug 修复迭代（13:10 – 13:40）——全部实跑取证

### Bug 1：分组绑定错乱 + 保底项选择逻辑颠倒（首跑即暴露）

首跑官方题输出异常：只显示「不吃辣」组、无辣不欢组消失、合计仅 ¥118.6：

```
【不吃辣 · 2 人】麦香鸡套餐 x2 ¥67
合计：¥118.6 / ¥150（结余 ¥31.4）
· 「无辣不欢」组原可升级 麦辣鸡腿堡三件套（券后），为保全桌不超支回退到 1+1 随心配（麦香鸡堡+中可口可乐）
```

**诊断**：
- 表结构按 `g["staple"]` 事后重选绑定，与降级后的实际行不符 → 辣组整组丢失；
- 保底项按「全菜单最低价」选取，导致辣组保底选中**不辣**的 1+1（12.9 < 22.9），再把 22.9 辣三件套当"升级项"，逻辑本末倒置。

**修复**：引擎重写为「满腹优先 + 预算修复回路」：
- 每组主食取「饱腹度最高中价格最低」（辣组保底即 22.9 三件套）；
- 超支时按「让位最多」原则把**整组**主食降级到红区 1+1，循环至可行；
- 行与组在添加时绑定（`group_key`），杜绝事后错配。

### Bug 2：小食补齐选了苹果片（应优先招牌薯条）

二跑结果正确但小食补了「苹果片 ×2」而非「中薯条」——两者同属 snack 类，苹果片更便宜。

**修复**：菜单数据给中薯条加 `staple: true` 招牌标记，补齐排序改为 `(是否招牌, 价格, 名称)`，保证"人人有薯"的故事成立。

### Bug 3：收尾理由的「结余」取错时点

两个圆筒的依据都显示同一结余（¥10.6）——理由在全部购买完成后才计算。

**修复**：购买时记录 `left_before`，依据反映当次决策时点的真实结余。

### Bug 4：降级记录引用泄漏变量，素食紧预算场景崩溃

22 条测试跑出 1 个 ERROR：`'NoneType' object is not subscriptable`——降级备注里引用了 `for` 循环泄漏的 `l` 变量（其 `from_item` 为 None）。

**修复**：先用 `old = g["staple"]` 捕获旧值再写备注。
